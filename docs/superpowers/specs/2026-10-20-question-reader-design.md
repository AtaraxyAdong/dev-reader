# IDEA 题目阅读工具窗口 — Design Doc

日期：2026-10-20
状态：设计已确认，插件实现及自动验证已开展；实际完成范围与未验收项见插件仓库的 `docs/reader-validation.md`。
对应实施文档：[Implementation Doc](../plans/2026-10-20-question-reader-implementation.md)

## 1. 需求与设计结论

用户希望在工作空余时阅读题目，阅读区域应贴近 IDEA 自带面板，减少对代码编辑区的占用。用户已经确认：

1. 支持左侧、右侧、底部三个停靠位置。
2. 拖动调整工具窗口尺寸时，内容自动适配实际可用宽高。
3. 题目列表和详情在同一个工具窗口内切换，并提供返回列表。
4. 获取题目内容后统一使用 Markdown 重新渲染，不继承网站页面样式。
5. 采用本会话最后一张效果图的布局：左右窄栏自然换行；底部宽栏仍为单列连续阅读。

这里的“三处支持”指同一个工具窗口可以移动到其中任意一处，不同时创建三个阅读器。移动、缩放窗口不改变当前题目。

### 当前展示链路

```text
题库内列表 / 全部题目 / 搜索结果
  → QuestionListManager 的打开题目回调
  → FileUtils.openNewEditorTab(...)
  → .msyc 虚拟文件 / FileEditor
  → ConvergePreview
  → BrowserFileEditor 加载远程页面
```

当前中间展示由 FileEditor 链路决定；网站样式来自远程页面。现有 ToolWindow 已能承载列表，但列表入口会创建新的 Content，不能只把浏览器组件搬入侧栏就认为改造完成。

## 3. 本期范围

交付一个完整阅读路径：题库／全部题目／搜索 → 题目列表 → 题目详情 → 返回原列表；详情支持题干、经验证的参考答案来源、上一题／下一题、查看原文。

第一版不扩展社区讨论的本地渲染、发帖或答题编辑功能；讨论通过“更多 → 查看原文”访问。登录和权限沿用现有站点能力，阅读器负责正确呈现状态。历史编辑器实现可保留作兼容，但新打开题目与切题流程必须进入工具窗口。

不在本期重构网站、替换后端、增加批量离线题库或同时维护多个阅读窗口。

## 4. 窗口、列表和详情交互

### 4.1 工具窗口

- 保留插件 ID `com.github.yuyuanweb.mianshiyaplugin` 和 ToolWindow ID `面试鸭`，与现有 `KeyConstant.PLUGIN_NAME` 一致。
- 阅读页面标题使用“阅读”；如需改变工具窗口可见名称，通过资源文案处理，不修改用于查找和保存布局的稳定 ID。
- 首次安装建议默认停靠右侧。已有用户位置以 IDEA 保存的布局为准，不在启动或打开题目时强制改回右侧。
- 使用 IDEA 原生移动、拖动缩放、隐藏与显示功能。窗口不主动抢焦点，不因后台请求完成而展开。
- 冷启动不主动展开；IDEA 自身恢复已保存的窗口布局时，插件不强行覆盖。
- 提供可在 Keymap 中配置的显示／隐藏 Action，不预占可能冲突的全局快捷键。

### 4.2 单窗口导航

一个 ToolWindow Content 内设置 `BANK_LIST`、`QUESTION_LIST`、`QUESTION_DETAIL` 三种页面，用 Swing `CardLayout` 切换。首页题库页与题目列表仍使用现有业务逻辑，拆掉它们自行创建 Content 的副作用。

只保留一套工具栏；根据当前页面切换动作集合：

| 页面 | 主要操作 |
| --- | --- |
| 题库／列表 | 原有题库、搜索、筛选、分页、登录入口 |
| 详情 | 返回列表、上一题、下一题、更多 |
| 更多菜单 | 查看原文、显示／折叠参考答案、账号相关入口 |

列表进入详情时保留原组件及其筛选条件、页码、排序、选中行和滚动位置。返回列表只切换页面，不重新创建或无条件刷新列表。进入另一题库或显式执行新搜索时才更新浏览上下文。

### 4.3 阅读与切题

- 详情按“标题 → 简要信息 → 题目 → 参考答案”连续排版，正文只有一个纵向滚动区域。
- 参考答案默认展开，允许折叠；一个题目的折叠状态和阅读位置在当前会话内保留。
- 题库上下题使用经核实的 `do_question_info` 返回顺序；接口只提供导航，不替代正文加载。
- 搜索／全部题目上下题使用打开详情时当前页的有序题目 ID 快照；到达边界后禁用对应按钮，不暗中跳到其他题库或自动请求下一页。
- 导航数据尚未返回或加载失败时，正文仍可阅读，上下题暂不可用。
- 切换到首次阅读的题目从顶部开始；返回已读题目可恢复其位置。隐藏／展开、停靠位置变化和主题变化保留当前进度。
- 请求未完成时显示当前题目的标题和加载状态，不让上一题答案继续挂在新题标题下。

## 5. 自适应与视觉规则

按阅读器实际 CSS viewport 和 Swing 逻辑尺寸布局，不按截图分辨率或物理屏幕像素计算。以下阈值是第一版实施基准，可在实际 IDEA 验收中微调并同步两份文档。

| 条件 | 布局 |
| --- | --- |
| 任意停靠位置 | 单列正文；工具栏固定，正文区域自适应剩余空间 |
| 正文 viewport 宽度 `< 480 CSS px` | 左右内边距 12 px；标题和元信息可换行；次要动作收进更多菜单 |
| 正文 viewport 宽度 `≥ 480 CSS px` | 左右内边距 16 px；正文最大宽度 960 px，靠左排布 |
| 正文 viewport 高度 `< 300 CSS px` | 上下内边距减至 8 px，收紧段落／标题间距；不缩小字号、不分栏 |
| 大于正文最大宽度 | 多余宽度留白，避免一行文字横跨整个底部窗口 |

正文宽度不得超过可用宽度；Swing 容器不设置会强行撑大工具窗口的固定首选宽度。工具栏使用可溢出布局，窄栏优先保留返回、切题与更多。

### 内容元素

- 字体、字号、背景、文字、边框及滚动条尽量跟随 IDEA；代码使用等宽字体。使用正常可读对比度，通过减少装饰实现安静的视觉效果。
- 长标题、链接和连续字符可折行。正文页面不出现整体横向滚动条。
- 图片 `max-width: 100%`、高度等比；加载失败显示简短占位及可操作的原链接。
- 代码块保留缩进与行边界，默认局部横向滚动，不为适配窄栏丢掉代码内容。
- 表格在独立容器内横向滚动，不能把整篇文章或整个工具窗口撑宽。
- 底部较矮时正常截取当前可见内容，通过纵向滚动继续阅读，不为了显示全部内容自动拆成题干／答案两列。

### 尺寸变化与进度

CSS 完成常规重排；尺寸变化不重新请求题目、不重新生成全文、不重建 JCEF。需要恢复位置时记录稳定内容块 ID 与块内偏移，避免只保存绝对像素 `scrollTop`。图片加载、字体变化及宽高改变后恢复同一阅读段落；更新做合并处理，避免滚动抖动和反复回写。

验收至少覆盖侧栏 `280×600`、`360×600`、`480×600`，底栏 `960×180`、`1440×240` 的逻辑尺寸，并覆盖 Windows 100%、150%、200% 缩放。小于这些尺寸时保留最佳可用布局，不承诺完整工具栏同时可见。

## 6. 数据与 Markdown 渲染

```mermaid
flowchart LR
    A[列表选择题目] --> B[SidebarController]
    B --> C[QuestionRepository]
    C --> D[现有登录会话与已核实接口]
    D --> E[题干与参考答案内容]
    E --> F[格式识别与 Markdown 规范化]
    F --> G[本地 HTML 模板与 IDEA 主题]
    G --> H[工具窗口中的单个 JCEF 阅读器]
```

### 6.1 必须完成的接口验证

已确认 `Question` 定义 `content`、`bestQuestionAnswer`；`QuestionAnswer` 定义 `content`、`contentType`，其中 0 表示富文本、1 表示 Markdown。但是：

1. 模型定义不能证明列表响应包含完整正文；必须检查真实获授权的响应是否省略或截断。
2. `bestQuestionAnswer` 不能未经核实就等同于远程推荐答案；社区回答第一页的第一条也不能代替参考答案。
3. 现有 `MianShiYaApi` 未声明题目详情接口。实施中必须依据实际契约接入，不预先编造 endpoint。
4. 题干缺少明确的格式字段；格式由已验证的接口契约确定。缺失或未知格式不能默认当 Markdown。
5. 需分别确认正常内容、会话失效、无权限、空答案及分页的实际响应。

数据适配层对外稳定提供“按题目 ID 加载详情”的能力。若列表已包含经证实的完整内容，可复用；否则接入经核实的详情来源。不依赖远程页面 DOM 或整页抓取作为静默兜底。

如果暂时无法取得真实样本，可以完成样本驱动的 UI 和转换组件；真实内容接入仍标记未验收，不能把演示数据当成可用接口。

### 6.2 内容规范化

- Markdown → 解析 → 插件自己的 HTML。
- HTML → 提取语义结构 → 转为 Markdown → 解析 → 插件自己的 HTML。
- 删除原网站布局、字体、颜色、内联样式、脚本及事件属性；保留标题、段落、列表、引用、强调、代码、链接、图片和表格。
- HTML 转换特别保留代码缩进、语言提示、图片真实地址及相对链接基址。
- 必需的 `<br>`、`<sub>`、`<sup>` 等语义元素可经过白名单处理，不保留任意原始 HTML。
- 采用 Java Markdown 管线，拟使用现有版本目录中的 flexmark 0.62.2，按需添加核心、表格和 HTML 转 Markdown 模块；先验证依赖解析与 Java 11 兼容，不直接引入全部扩展。
- JCEF 只加载本地生成的文档与随插件分发的样式／脚本；外链交给系统浏览器，文内锚点留在阅读器。
- 远程图片不继承任意站点 Cookie。若确需认证资源，以核实后的资源域名和权限机制单独处理。

不支持的格式给出明确提示和“查看原文”，保留可展示的内容，不显示成空答案。

### 6.3 加载状态

| 情况 | 用户看到的内容 |
| --- | --- |
| 加载中 | 当前题目标题与轻量加载提示 |
| 题干、答案正常 | 连续 Markdown 正文 |
| 题干正常、答案无权限 | 保留题干，在答案位置说明权限状态 |
| 未登录／会话失效 | 登录入口；仅用户主动点击后进入登录流程 |
| 用户取消登录 | 保留页面和登录入口，不循环弹窗 |
| 确认无答案 | “暂无参考答案” |
| 接口异常／超时 | 明确的加载失败提示及重试 |
| 格式未知／不支持 | 格式提示及查看原文 |
| 题目不存在 | 不存在提示及返回列表 |

现有响应拦截器在业务码 `40100` 时自动弹出登录。阅读请求需要独立的静默处理策略，避免后台取题或多个请求反复弹窗；保留现有主动登录入口。`40102` 等权限码必须按已验证的接口契约映射。

## 7. 组件边界与生命周期

| 组件 | 职责 |
| --- | --- |
| `SidebarController` | 当前页面、当前题目、导航上下文、会话内进度、请求代次、返回列表 |
| `QuestionRepository` | 调用真实接口、复用登录会话、区分加载结果、题干和答案权限 |
| `ContentNormalizer` | 按格式规范化为 Markdown，保留语义 |
| `MarkdownRenderer` | Markdown 转正文 HTML，不负责网络和窗口导航 |
| `QuestionReaderPanel` | 单个 JCEF、详情视图、本地模板、滚动位置与主题更新 |
| `SidebarPanel` | 唯一根容器、唯一工具栏、三种页面的切换 |

控制器按项目隔离；全局 Action 必须从事件的 Project 取得当前控制器，不能持有其他项目的面板。

网络与内容转换在后台执行。更新工具窗口通过相应的 UI 调度进入 EDT。每次选题递增请求代次；回调必须同时校验代次、题目 ID、会话代次以及组件未释放。取消请求只是减少资源消耗，过期校验才是最终防线。

详情隐藏到列表或工具窗口收起时保留组件与进度；返回列表时使未完成的详情请求失效，避免迟到响应切回详情。注销或切换账号时取消请求、清空正文与账号关联状态，清理列表内容并回到需要重新加载的浏览页。

唯一 Content 的 disposer 管理控制器；控制器管理浏览器、消息总线订阅、后台任务和页面组件。主题变化只更新本地样式，不新建浏览器。项目关闭后所有回调失效。仅在首次进入详情时初始化 JCEF；不支持 JCEF 时显示可理解的提示与查看原文入口。

位置和尺寸由 IDEA 管理。第一版只承诺当前项目会话内保留阅读状态，不将答案或登录凭据写入新的持久化缓存。

## 8. 方案取舍

| 方案 | 判断 |
| --- | --- |
| 将当前远程页面直接搬到工具窗口 | 可改变位置，但保留网站样式，不满足本需求 |
| 依赖 IDEA Markdown 插件内部预览组件 | 增加插件和版本耦合，不作为本期方案 |
| Swing 工具窗口 + 独立 Markdown 管线 + 现有 JCEF | 选用；复用现有能力，同时控制阅读样式与响应式行为 |

保留 Java 11 和现有构建基准，避免在功能改造中顺带升级整套构建。用户实际 IDEA 版本需在实施准备阶段核实；若超过已声明范围，单独处理兼容性，不仅扩大 `untilBuild`。尤其 JCEF 在 IDEA 2026.2 的依赖声明已有变化，不能将最新 SDK 写法直接套到 2021.3 基准。

## 9. 验收标准

1. 左侧、右侧、底部均能完成列表 → 详情 → 返回列表；中间不新增题目编辑器。
2. 移动、连续拖动缩放时保持当前题目；正文自适应，不新增请求或浏览器实例。
3. 搜索、题库及全量列表均走统一入口；返回后筛选、页码、选中行和滚动位置保留。
4. 窄栏长标题、图片、代码、表格均可阅读；只有代码／表格允许局部横向滚动。
5. 底部始终单列，保持合理行宽；浅色／深色主题与系统缩放均可用。
6. Markdown 与 HTML 样本经转换后内容完整，网站样式不进入阅读器。
7. 快速切题、返回、注销、关闭项目时，过期响应不得覆盖当前页面或恢复已清空内容。
8. 登录取消、无权限、无答案、网络失败、格式未知显示不同状态。
9. 两个项目同时打开时，选题、账号状态处理和控件实例不会串项目；共享登录变化通知到各项目。
10. 构建、兼容性检查和目标 IDEA 手工验证有记录；真实接口未验证时不得宣称完整交付。
